**数字结论（首段）：** ezOne 流水线支持 **4 类触发**（代码事件/定时/手动/API）、**22+6 个内置系统环境变量**、Job 级串/并/跳过三态、**7 大类约 25 种插件**（含人工审批、子流水线触发、覆盖率门禁、SonarQube 门禁）；制品库 **11 类仓库**且半成品/成品成对、发版插件自动打 Tag 并把四位构建版本归档为三位发布版本；主机部署以**主机组（Agent）+ 部署模板**为底座、任务单可挂审批；另有我的工作台聚合待办、按模块授权的个人访问令牌、全量 Swagger API、企业微信/钉钉/邮件/站内信通知。

## 1. 流水线（ezPipeline）实证

### 1.1 触发方式（S2）

| 触发类 | 官方形态 | 关键参数 |
|---|---|---|
| 代码事件 | 代码更新（push/合入）、发起及更新 MR 评审、收到及更新 DCR 评审、评审模拟预合入（专利功能） | 关联分支：精确匹配 / 全部分支 |
| 定时 | 定时触发，对分支最新 commit 构建 | 可设"相对上次触发有代码变更才触发"、单次/循环；规则为类 Cron 表达式 |
| 手动 | 列表页点执行按钮，弹"流水线执行确认"对话框 | 可选分支（下拉筛选）、**环境变量表可当场改值**（预填默认值、可加行） |
| API | `POST /v1/pipeline/pipelines/{id}/manual`，Header `access_token:{个人令牌}` | body：`externalName`（分支/tag/commit）、`scmTriggerType=BRANCH|TAG|COMMIT`、`variables`；令牌在个人设置→访问令牌新建，授流水线读写 |

### 1.2 编排与执行策略（S1/S2）

| 维度 | 官方形态 |
|---|---|
| 结构 | Stage 串行；Stage 内 Job 串行/并行可选；拖拽编排 |
| Job 触发方式 | 每个 Job 前 icon 三选：自动触发 / 手动触发（执行时等人点）/ 程序控制（按环境变量值决定"跳过"或"停止后待手动执行"） |
| 并发策略 | 流水线级并发实例数上限，超限排队或中止可配 |
| 超时 | 单任务超时分钟数（1–120 分钟），超时取消 |
| 基准设置 | 可选基准分支，注入 `SYS_BUILD_BASE_COMMIT`，供增量编译/扫描/覆盖率比对 |
| 历史 | 执行记录保留 180 天；执行记录页 Stage 可展开 Job、右浮窗看日志 |
| 其他 | 流水线标签筛选、流水线版本变更历史、多人同时编辑冲突预警、转授权（触发人借用被授权人设置） |

### 1.3 环境变量三级（S2）

| 级 | 说明 |
|---|---|
| 系统变量 | 22 个流水线级（`SYS_PIPELINE_BUILD_NUMBER` 构建号、`SYS_BUILD_BRANCH/COMMIT`、`SYS_BUILD_SNAPSHOT_VERSION` 构建版本、`SYS_BUILD_RELEASE_VERSION` 发布版本、`SYS_LAST_RELEASE_VERSION`、`SYS_BUILD_BASE_COMMIT` 等）+ 6 个任务级（`SYS_WORKSPACE`、`SYS_CI_TOKEN` 任务期临时令牌等） |
| 用户静态 | 流水线编辑器"环境变量"标签页维护，支持**密文显示**开关；脚本里 `${VAR}` 引用；每个变量可勾选"触发时设置"（手动触发对话框可改值、且允许被动态变量覆盖） |
| 用户动态 | 插件脚本在工作空间根目录写 `runtime_variables.txt`（`key=value` 逐行），下一个 Job 起生效；禁改 SYS 前缀 |

### 1.4 插件七大类（S2）

| 类 | 代表插件 | 质量门禁形态 |
|---|---|---|
| 编译构建 | 代码打包 / Gradle 编译 / Maven 编译 / npm 编译 | 开"制作文件制品包"开关 → 自动上传半成品库 |
| 构建镜像 | Dockerfile 构建、多平台（arm64+amd64）、推送镜像半成品库/外置源 | — |
| 发版 | 发版插件：给代码库打 Tag + 把本次半成品归档成品库（四位构建版本 → 三位发布版本） | — |
| 部署 | 主机部署插件（选主机组 + 部署模板 + 半成品/成品）、Helm 部署、K8S 部署发单、Yaml 部署 | — |
| 测试 | 内置接口测试套件、性能测试、Cobertura 覆盖率、Jacoco 覆盖率、JUnit、Maven 单测、JMeter | 分支覆盖率/行覆盖率/通过率阈值，低于阈值任务失败 |
| 扫描 | 内置代码扫描、SonarQube（项目 token） | Bugs/漏洞/异味 级别 + 数量阈值（如"出现漏洞 级别以上且总数超 10 个"） |
| 通用 | shell 命令、**人工审批**（流程中挂自定义审批流）、**触发下游流水线**（子流水线）、Docker 镜像执行器、JenkinsJob | — |

### 1.5 通知与关联（S1/S2/S14）

- 流水线编辑器"通知提醒"：成员 = 触发者 + 可加人；事件 = 开始/成功/失败，按人勾选。通道：企业微信、钉钉、邮件、站内信（S1）。
- **流水线关联卡片**：执行记录按触发事件解析本次 commit 提交信息中的卡片编号，自动聚合需求/缺陷卡片到执行记录页（手动触发取所选分支提交、代码更新取合入 commit、评审场景取源→目标分支 commit 差）。发版插件可按"基准 vs 触发分支"的 commit 差圈定本次发布涉及卡片。

## 6. 对自建系统的落地建议（2026-10-14 修订）

**已被 DevFusion 采纳并落地（对照代码）：** Stage×Job 两级、手动+Webhook 触发、run 快照、日志流式、取消、失败阻断+continueOnFail、构建成功自动归档制品、部署单四步模拟、回滚=重新部署旧版本。

**值得照抄的版本协议：** 半成品（构建版本）/ 成品（发布版本）成对 + 发版插件归档晋级（S4/S5）——DevFusion 现仅单层制品，晋级动作是缺口。

**本地可模拟、闭环收益高：** ① 手动触发对话框带参数变量表（S2）；② Job 级并行（S1）；③ 人工审批 Job（挂起→审批通过才续跑，S2）；④ 质量门禁阈值（通过率/覆盖率数字开关，S2）；⑤ 部署单审批开关（S8）；⑥ 我的工作台（我负责的工作项+待审批聚合，S9）；⑦ 个人访问令牌 + API 触发（S10/S2 curl 样例）；⑧ 流水线执行记录关联工作项编号（commit 信息解析，S2）。

**建议列入非目标（依赖外部系统）：** 真实 Git 托管与 MR/DCR/模拟预合入（S2）、真实 Agent/主机 SSH 部署（S6）、K8S 编排（S2）、企业微信/钉钉/邮件真实推送（S1）、SonarQube 外部服务（S2）、多租户（S13 对应企业版）。

**推断与实证分界：** 上文表格内容均来自 S1–S14 页面实证；"回滚靠重新部署旧版本"在 ezOne 文档未见专章，属同类平台惯例推断（非官网事实）；灰度/蓝绿的具体编排步骤官网仅一句话带过（S7），细节未实证。
